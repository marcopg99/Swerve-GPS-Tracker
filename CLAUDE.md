## Project

Single-module Android app (`:app`) that records GPS tracks to a local Room database, displays them on an OpenStreetMap-based map, and exports them as GPX files. Tracks can have a **cover image** and store a computed **distance**. Package: `com.mpg99.gpstracker`. UI strings are in Spanish.

- Kotlin 2.0.21, AGP 8.7.3, Compose BOM 2024.12.01
- `minSdk = 29`, `targetSdk = 35`, JDK 17
- Version catalog in `gradle/libs.versions.toml` — add new dependencies there, not directly in `app/build.gradle.kts`
- Image loading via **Coil** (`io.coil-kt:coil-compose`) — loads cover images from internal-storage `File` paths, offline.
- Release builds are signed with the **debug keystore** (`signingConfig = signingConfigs.getByName("debug")` in `app/build.gradle.kts`), so `assembleRelease` produces an installable, signed APK. Installing over a copy signed with a different key fails with a package-conflict error — uninstall first.

## Commands

```bash
./gradlew assembleDebug                 # build debug APK
./gradlew installDebug                  # build + install on connected device/emulator
./gradlew test                          # JVM unit tests
./gradlew connectedAndroidTest          # instrumented tests (needs device)
./gradlew :app:testDebugUnitTest --tests "com.mpg99.gpstracker.SomeTest"   # single test
./gradlew lint                          # Android lint
./gradlew clean
```

There is no separate lint/format step beyond Android lint; Kotlin style is `kotlin.code.style=official`. Room schemas are generated by KSP, not kapt — if Room codegen seems stale, `./gradlew clean` and rebuild.

## Architecture

Layering (all under `app/src/main/java/com/mpg99/gpstracker/`):

- **`data/`** — Room. `Track` (1) ↔ `TrackPoint` (N) with `ForeignKey.CASCADE`. `Track` carries `coverUri: String?` (absolute path to a cover image in internal storage) and `distanceMeters: Double` (maintained, not derived at read time). `TrackDao.observeTrackSummaries()` returns `TrackSummary` (a non-entity projection that also exposes `coverUri` and `distanceMeters` plus the joined `pointCount`). `AppDatabase` is a manual lazy singleton via `AppDatabase.get(context)`; DB name `gpstracker.db`, **currently version 3**. Schema changes need a `Migration` added to the `addMigrations(...)` call: `1→2` added `coverUri`, `2→3` added `distanceMeters`. `TrackRepository` wraps the DAO and is the single API surface the rest of the app uses.
- **Distance tracking** — `Track.distanceMeters` is maintained three ways, all using `util.haversineMeters` over consecutive points so the value always matches what the detail screen computes live: (1) `TrackingService` keeps a running total as points arrive and calls `repo.setDistance`; (2) `TrackRepository.finishTrack` recomputes accurately from all stored points on stop; (3) `TrackRepository.importTrack` computes it for imported GPX. `GPSTrackerApp.onCreate` runs `repo.backfillDistances()` once in a background coroutine to fill in tracks recorded before this column existed (rows where `distanceMeters == 0`). The **detail screen computes its own distance from points** (`TrackDetailViewModel`) rather than reading the column, so it is always correct even mid-recording.
- **`service/TrackingService`** — foreground service (`foregroundServiceType="location"`) that owns the FusedLocationProvider subscription and writes points through the repository. Started/stopped via the static `TrackingService.start(context)` / `stop(context)` helpers. Exposes its current state to the UI through a **process-wide static `StateFlow<TrackingState>`** (`TrackingService.state`) — that is intentionally the source of truth for "is a track currently being recorded?", because the service may outlive the Activity. Also keeps `lastLat/lastLon/runningDistance` fields (reset on start/stop) to maintain live distance. Constants for sampling cadence (`LOCATION_INTERVAL_MS = 5s`, `LOCATION_FASTEST_INTERVAL_MS = 2s`, `LOCATION_MIN_DISTANCE_M = 5m`) live in its companion.
- **`ui/`** — single-Activity Compose app. `MainActivity` → `AppNavigation` (NavHost with `home`, `record`, `list`, `detail/{trackId}` routes). Each screen has its own `ViewModel` with a hand-rolled `viewModelFactory` companion that pulls the repository off `GPSTrackerApp` via `APPLICATION_KEY`. There is **no DI framework** — `GPSTrackerApp.repository` is the injection point; new ViewModels should follow the same `Factory` pattern (see `HomeViewModel`).
  - **`ui/home`** — dashboard: header with app name + rounded logo, an "Última ruta" card (cover + name + date + duration + distance, tappable to detail), and two bottom buttons "Nueva ruta" (→ `record`) / "Rutas" (→ `list`). It does **not** contain the recording controls.
  - **`ui/record`** — `RecordScreen`/`RecordViewModel`: the actual recording UI (runtime-permission requests, elapsed timer, live point count, Iniciar/Detener). This is where a new track is created via `TrackingService.start/stop`.
  - **`ui/list`** — track list; each card mirrors the home "Última ruta" card (cover on top, then data) plus share/delete actions.
  - **`ui/detail`** — map + stats; top-bar action opens the Android **photo picker** (`ActivityResultContracts.PickVisualMedia`) to set/replace the cover. **Points count is shown only here**; home and list summaries show distance instead.
  - **`ui/components/TrackCover.kt`** — shared composable that renders a cover from an internal path (Coil `AsyncImage` of a `File`) or a placeholder icon when null.
- **`gpx/GpxExporter`** — writes a GPX 1.1 file to `filesDir/gpx/` and returns a share `Intent` via `FileProvider`. The authority is `${applicationId}.fileprovider` and is wired in `AndroidManifest.xml` + `res/xml/file_paths.xml`; don't change one without the other.
- **`util/Format.kt`** — shared formatting helpers (`formatDateTime`, `formatGpxTime`, `formatDistance`, `formatDuration`, `haversineMeters`). Reuse these rather than reformatting in screens.
- **`util/CoverStore.kt`** — copies a picked image `Uri` into `filesDir/covers/` (timestamped filename to defeat image caches; deletes the previous file) and returns the absolute path stored in `Track.coverUri`. Cover files are deleted when their track is deleted (see `TrackListViewModel.deleteTrack`).

**Theme** — `ui/theme/Theme.kt` forces a **dark green** Material 3 palette always: dynamic color is disabled and there is no light scheme. `MainActivity` forces light system-bar icons via `enableEdgeToEdge(SystemBarStyle.dark(...))`, and `res/values/themes.xml` + `values-night/themes.xml` both use the dark `@color/app_background`.

Map rendering uses **osmdroid** (`org.osmdroid:osmdroid-android`), not Google Maps. `GPSTrackerApp.onCreate` configures osmdroid's user agent and points its tile cache at `getExternalFilesDir("tiles")` — this must run before any `MapView` is inflated, so keep that init in the `Application` subclass.

### Permissions & runtime behavior

The manifest declares `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`, `ACCESS_BACKGROUND_LOCATION`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION`, and `POST_NOTIFICATIONS`. The service self-stops if `ACCESS_FINE_LOCATION` is missing — runtime permission requests are the UI layer's responsibility before calling `TrackingService.start`. On Android 14+ (`UPSIDE_DOWN_CAKE`) the service calls `startForeground` with the explicit `FOREGROUND_SERVICE_TYPE_LOCATION` flag; preserve that branch when touching `startForegroundCompat`.
